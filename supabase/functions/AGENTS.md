- Auto3 original analysis (`_shared/auto3-analysis.ts`, stored in `auto3_oneshot_preparations`) only classifies perspective/quality and picks ONE OneShot master (`_shared/auto3-master.ts`); paid background processing requires an explicitly approved `vehicle_processing_profiles` row with a per-vehicle credit cap, because credits must never be spent without the dealer's explicit consent.
- Auto3 → OneShot automation runs in the `auto3-processing-job` edge function (one step per tick, DB lease, self-kick, pause on 402/budget) and calls the existing generators via the service-role internal actor (`_shared/internal-actor.ts`), because background jobs must not depend on an open browser while generators keep charging credits themselves.
- Capture calls opt into `_shared/remaster-gallery.ts`: validate ownership before charging and save each image with the user-scoped client before response; failed delivery refunds through the existing handler, because paid results must survive a closed browser.
- Browser and remaster billing share `_shared/remaster-cost.ts`, with exact-tier configured costs and identical fallbacks, because missing test-tier prices must not silently inherit the Schnell price.
- Vehicle-image credit floors are tier-aware through `_shared/image-credit-floor.ts`; OneShot estimates reuse the remaster resolver, so configured image prices are not overridden by hidden minimums.
